# セッション解析のメンテナンス

このリポジトリの開発用Skill。ログの全バージョンへの互換性を保証するものではない。
実装契約は[セッション解析JSON仕様](../../../docs/session-analysis.md)を正本とし、
外部ログの観測とは区別する。

## 調査の入口

- [ログ仕様の調査記録](references/log-format-notes.md)で、確認済みの情報と未確認事項を読む。
- Codexの形式や挙動を確認するときは、利用可能な `openai-docs` Skillを読み、その手順で
  公式情報を調べる。利用できなければ調査上の制約を報告し、取得していない情報を断定しない。
- 公式資料の記述、ローカルログの観測、現在の実装、設計案を区別する。資料の日付・URL、
  観測範囲、確認できたバージョンを記録する。公開資料にない構造を固定された公開仕様と呼ばない。
- 調査結果は関連するreferenceへ追記・更新する。機密本文、個人情報、個人パス、
  セッション識別子を転載せず、構造と匿名化した最小例を残す。

## 責務と変更範囲

- CLIはローカルログの機械的な抽出・対応付け・欠落表示を担当する。Codex側のSkillが意味を解釈する。
  MCPサーバーにCodexホストのログ読取を追加しない。
- `refinery-review-session` は根拠付きレポートまでで完了する。
  `refinery-propose-improvements` は別の明示依頼で、1件または複数のレポートから改善案を比較する。
- 調査や仕様整理の依頼では実装を変更しない。変更を依頼された場合は、対象のSkill、
  `src/knowledge_refinery/session_ops.py`、`session_cli.py`、関連テスト・文書を照合する。
  既存実装の挙動をそのまま外部ログ仕様の根拠にしない。

## 完了時

調べた事実、未確認事項、実装への影響を日本語で報告する。変更時の検証はrepoのAGENTS.mdに従う。
Skillの判断について静的確認と実モデル試験を区別し、未実施の検証を成功扱いにしない。
